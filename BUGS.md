# Bug hunt before release

Date: 2026-10-09. Method: static checks and a headless Chrome (puppeteer) play-through of `dist/`. **No game code was changed in this pass.**
For the tests I built a throw-away copy in the scratchpad that only adds `window.game` and a few module exports, so the scripts could read the game state. The game code is identical.

Fixes below are only proposals. "Touches scoring/data/hints" is **No** for every one of them. Where the problem is in scoring.ts or src/data, it is flagged and not fixed.

## What I checked and found OK

- **Static:** `npx tsc --noEmit` and `npm run build` pass with no errors. The build warning is only the Phaser chunk (JS bundle 1,525 kB, 405 kB gzip). Assets over 2 MB in `dist/`: `ending_lose.mp3` 2.84 MB, `title_music.mp3` 2.81 MB (and the 193 MB `.aup4`, see #2). `dist/` without the `.aup4` files is 29.3 MB.
- **Leftovers:** no `console.log`, TODO, FIXME or `debugger` in `src/`. The only TEMP code is the dev code in #1.
- **Assets:** every image, sound and font that the code loads exists on disk (exact-case check, since macOS ignores case). All 11 customer portraits and the 3 player portraits exist. There were no 404s, no `loaderror` warnings and no console errors in any run. The only unused game files are in #6 and `button_round.png` (#11).
- **Words:** no "$" or "dollar" left in game text. The only "Ottoman" wording is #7.
- **Full play-throughs** (real clicks, real time): Easy + story read + tutorial completed + all 10 customers all 3★ -> Great win (30 / 18); Normal + story skipped + tutorial skipped + 6 x 3★, 4 x 2★ -> Win (26 / 22); Hard + tutorial completed + all 2★ -> Lose (20 / 26). The money after each customer was right (3★ = 3, 2★ = 2). The coin pile, HUD, day / evening and the endings worked each time. No console errors or warnings.
- **Reset:** after Pause -> Restart, after Ending -> Main menu -> new game, and after 10 x Play again: money 0, HUD "0 / 22", empty cash box, Day 1 morning, 0 smells, no ghost drops, no hint in the order note, no player reply, morning ambience, tutorial flag unchanged, one music instance.
- **Pause (Esc)** during: pour, waste pot, stir, react reply typing, coin animation, customer leaving, practice typewriter, tutorial step. Every time the scene time froze, the playing effects paused, and Resume continued with no duplicate sounds and no stuck input; the typewriter went on from the same character. Esc during the footsteps fade is ignored on purpose (the fade covers the screen). Esc during the title sign fall does nothing (the title has no pause menu) and breaks nothing.
- **Spam:** 3-4 quick clicks on Make perfume, a bottle, Let them smell, Adjust, Next customer, Play, Enter / Space, Yes (Start on Normal?) and Skip (story and tutorial) never start a second transition: `scene.start` ran once per action. (Deliver: see #3 and #9.)
- **Overlays:** Notebook -> Esc closes only the notebook; the next Esc opens the pause menu; Settings -> Endings -> preview over Title and over Pause. After Back the music duck returned to the right value (1 on the title, 0.4 in the pause menu), the ending music stopped, and there was one music instance. Esc during a preview works like Back.
- **Limits:** with fewer than 3 drops, Smell is disabled and Deliver is not available. The 7th drop is ignored. Empty on 6 drops and on an empty flask is fine. Empty during a pour is ignored. When smells run out, Deliver takes the place of Smell and the "no smells" note shows; the Deliver click works.
- **Focus:** switching tabs suspends the audio context and brings it back on return (checked on the title and in the shop). There was no doubled music or ambience.
- **Volume / mute:** master 0, music 0 and mute silence the title music, ending music and ambience. The footsteps volume follows the effects slider.
- **No storage** (localStorage throws): the game loads, plays and the tutorial runs. Settings changes do not crash. (Only #4.)
- **Leaks:** over 10 restarts via the ending ("Play again") the numbers stayed flat: keyboard and input listeners, scene event listeners, tweens, timers, display-list size, sounds. The tutorial's looping outline tweens are cleaned up as the steps change.
- **Text:** the longest order (Old Kemal) and the longest hint fit in the order note, the speech bubble and the reply bubble at 1280x720. The great-win and lose texts fit their bands.

## Things I could not test

- **Sound by ear:** actual loudness balance, fades, the coin pitch variation, the footsteps timing, the ending music, and whether any sound clicks or doubles audibly. I only checked sound objects, volumes and counts.
- **The browser's autoplay lock.** The test browser was started with autoplay allowed, so the "audio unlocked by the first click" path was not run.
- **Real window blur** (clicking another app). I could only switch tabs in headless Chrome.
- **Other browsers and devices:** Safari, Firefox, mobile / touch, high-DPI screens, and resizing the window (Phaser FIT scaling).
- **itch.io embed:** the iframe, fullscreen, and the zipped upload (the final file names and sizes).
- **Not driven end to end:** a 1★ ("haggled") delivery with the coin animation; "Replay tutorial" followed by a new game; pausing during the Day card or the story pages; Hard and Easy with mixed star results; very slow machines.
- The Canvas (non-WebGL) renderer fallback.
